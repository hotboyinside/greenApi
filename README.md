# GREEN API

React-приложение для отправки и получения текстовых сообщений в MAX через GREEN-API.
Поддерживает подключение к инстансу, создание чатов по номеру получателя,
отправку сообщений и получение ответов через HTTP API.

## Стек

- React и TypeScript — интерфейс и типизация.
- Vite — сервер разработки и сборка.
- CSS Modules — стили компонентов.
- React Hook Form — управление формами; Yup — валидация;
  `@hookform/resolvers` — подключение схем Yup к формам.
- Lucide React — SVG-иконки.
- Vitest и React Testing Library — тестирование логики и интерфейса;
  jsdom — окружение DOM для тестов.
- ESLint и Prettier — проверка кода и форматирование.
- Playwright — браузерные тесты; GitHub Actions — CI и публикация.

## Требования

- Node.js 24.
- pnpm — версия указана в поле `packageManager` в `package.json`.
- Инстанс GREEN-API, авторизованный в MAX.

## Локальный запуск

Установить зависимости:

```powershell
pnpm install
```

Создать локальный файл настроек:

```powershell
Copy-Item .env.example .env.local
```

В `.env.local` указать `VITE_GREEN_API_URL` — значение `apiUrl` из настроек
инстанса в личном кабинете GREEN-API. Не добавлять путь метода, `idInstance` или токен.

Для получения сообщений включить `incomingWebhook` в настройках инстанса
и оставить `webhookUrl` пустым. После изменения подождать около минуты.

Запустить сервер разработки:

```powershell
pnpm dev
```

Открыть адрес из терминала и подключиться с помощью `idInstance` и `apiTokenInstance`.

## Переменные окружения

| Переменная           | Назначение                           |
| -------------------- | ------------------------------------ |
| `VITE_GREEN_API_URL` | Базовый адрес GREEN-API для запросов |

После изменения `.env.local` перезапустить сервер разработки.
Для опубликованного приложения потребуется новая сборка.

## Хранение данных

Учётные данные, чаты и сообщения хранятся только в памяти текущего подключения.
Так токен и переписка не сохраняются в хранилище браузера между сессиями.
После выхода или обновления страницы нужно подключиться заново; локальная переписка
очищается. История сообщений с сервера не загружается.

## API-клиент

Код в `src/api` разделён на `client` (методы), `transport` (HTTP-запросы и ошибки)
и `contracts` (типы и проверка ответов). Названия методов находятся в `endpoints.ts`.
Публичный интерфейс экспортируется через корневой `index.ts`.

Клиент использует `fetch`: проверяет состояние инстанса через `getStateInstance`,
получателя через `checkAccount` и отправляет текст через `sendMessage`.
Входящие сообщения получает последовательным опросом `receiveNotification`,
после обработки подтверждает их через `deleteNotification`.

Предусмотрены таймауты, отмена запросов и обработка ошибок. Отправка сообщений
автоматически не повторяется. Одновременно с очередью инстанса должен работать
один потребитель.

## Проверки

```powershell
pnpm lint
pnpm typecheck
pnpm format:check
pnpm test:run
```

Для браузерных тестов установить Chromium и запустить Playwright:

```powershell
pnpm exec playwright install chromium
pnpm test:e2e
```

## Дополнительные команды

- `pnpm format` — форматирование файлов.
- `pnpm test` — тесты в режиме наблюдения.
- `pnpm build` — проверка типов и сборка в `dist`.
- `pnpm build:ci` — проверочная сборка с фиктивным API и путём `/greenApi/`.
- `pnpm build:pages` — сборка для публикации; требует `VITE_GREEN_API_URL` в окружении.
- `pnpm test:e2e:ui` — интерактивный запуск браузерных тестов.
- `pnpm test:e2e:debug` — отладка браузерных тестов.
- `pnpm preview` — локальный просмотр готовой сборки после `pnpm build`.
