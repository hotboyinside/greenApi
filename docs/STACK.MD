# Предлагаемый стек

Проект — небольшое SPA для отправки и получения текстовых сообщений в MAX через GREEN-API.

| Инструмент                                            | Назначение                                                                   |
| ----------------------------------------------------- | ---------------------------------------------------------------------------- |
| React + TypeScript                                    | Компоненты интерфейса и типизация сообщений, чатов и ответов API             |
| Vite                                                  | Локальный сервер разработки и сборка приложения; стартовый шаблон `react-ts` |
| CSS Modules                                           | Стилизация интерфейса под внешний вид MAX                                    |
| Нативный `fetch`                                      | Запросы к GREEN-API с обработкой ошибок и отменой через `AbortController`    |
| `useReducer` + Context                                | Общее состояние сессии, чатов и сообщений                                    |
| Vitest                                                | Модульные тесты логики чатов, сообщений и цикла получения уведомлений        |
| React Testing Library + user-event + jest-dom + jsdom | Проверка компонентов через действия пользователя и состояние интерфейса      |
| MSW (Mock Service Worker)                             | Подмена ответов GREEN-API в интеграционных тестах                            |
| Playwright                                            | Сквозные тесты основного сценария в браузере                                 |
| ESLint + Prettier                                     | Проверка и единое оформление кода                                            |
| pnpm                                                  | Управление зависимостями                                                     |

## Работа с GREEN-API

- Отправка текстовых сообщений через `SendMessage`.
- Получение сообщений отдельным последовательным циклом long polling: `ReceiveNotification` → обработка уведомления → `DeleteNotification`.
- Отмена активного запроса при выходе из сессии и остановка цикла получения.
- Учётные данные `idInstance` и `apiTokenInstance` хранятся в памяти на время сессии.

## Тестирование

Проверяем поведение приложения и критические сценарии. Автоматические тесты используют фиктивные учётные данные и подменённые ответы API, чтобы запускаться без реального аккаунта MAX.

### Модульные тесты — Vitest

- Валидация и нормализация номера телефона.
- Обновление состояния чатов и сообщений, защита от повторного добавления сообщения.
- Обработка уведомлений: текстовые сообщения, неподдерживаемые события и пустая очередь.
- Последовательность получения и подтверждения уведомлений, восстановление после временной ошибки и остановка при выходе из сессии.

### Компонентные и интеграционные тесты — React Testing Library + MSW

- Ввод учётных данных и отображение ошибки подключения.
- Создание чата по номеру телефона.
- Отправка сообщения, состояние ожидания и обработка ошибки отправки без потери введённого текста.
- Отображение входящего сообщения в соответствующем чате.
- Запрет отправки пустого сообщения.

Для взаимодействия с интерфейсом используем `user-event`, для проверок DOM — `jest-dom`, для окружения компонентов — `jsdom`. MSW подменяет сетевые ответы, сохраняя работу реального API-клиента приложения.

### Сквозные тесты — Playwright

- Основной сценарий: подключение → создание чата → отправка текста → получение и отображение ответа.
- Выход из сессии и возврат к форме подключения.

На старте запускаем сквозные тесты в Chromium. Ответы GREEN-API подменяем через перехват запросов Playwright.

### Ручная проверка

Перед выпуском проверяем отправку и получение сообщений с реальным инстансом GREEN-API и получателем в MAX. Это подтверждает интеграцию, которую тесты с подменёнными ответами не проверяют.

### Планируемые команды

Команды добавим в `package.json` при настройке проекта:

| Команда              | Назначение                                                                             |
| -------------------- | -------------------------------------------------------------------------------------- |
| `pnpm test`          | Vitest в режиме наблюдения                                                             |
| `pnpm test:run`      | Однократный запуск модульных и интеграционных тестов                                   |
| `pnpm test:coverage` | Отчёт покрытия через `@vitest/coverage-v8` для поиска непроверенной критической логики |
| `pnpm test:e2e`      | Сквозные тесты Playwright                                                              |

## Основные части приложения

1. Форма подключения к GREEN-API.
2. Список чатов.
3. Создание чата по номеру телефона получателя.
4. Окно переписки и форма отправки текстового сообщения.

На старте предлагается SPA без собственного бэкенда. Дополнительные библиотеки будем добавлять по мере появления конкретной необходимости.
